## 先算延迟，再决定要不要“欧洲”

机房选在哪，取决于用户在哪：服务欧洲本土用户，欧洲机房是刚需；用户横跨欧美，美国东海岸往往是更灵活的折中；用户主要在国内，欧洲VPS没有优化线路就是自找麻烦。

道理不复杂。光在光纤里大约每秒传播20万公里，折算下来每传输100公里就多1ms往返延迟。按公开的典型值，美国东海岸到伦敦约78ms，到法兰克福约88ms。这个数字放到实际访问里会被放大：建立一条新的HTTPS连接要三次往返（TCP握手、TLS握手、发请求），欧洲用户打开你的网站，等首字节就要234ms上下；页面如果串行调六个接口，光等网络就是468ms。

反过来看，一台美东机器服务欧洲用户，同样是七八十毫秒的量级。所以用户在美国东部和欧洲两头都有的场景，美东机房经常是更划算的落点，而不是非“欧洲”不可。

国内访问是另一回事。中欧之间物理距离摆在那里，延迟低不下来，普通国际线路晚高峰还容易拥堵丢包。专门做回国优化的欧洲VPS（电信CN2 GIA、联通AS9929这类线路）之所以单独成一个品类、价格贵好几倍，原因就在这。
